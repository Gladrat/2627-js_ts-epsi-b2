# Exercice 4 : Faire réagir l’interface au cours choisi

La liste des cours est déjà affichée.

Ajouter dans le HTML :

```html
<p id="course-message">
  Aucun cours choisi
</p>
```

Puis faire évoluer l’interface pour que chaque cours possède un bouton **Tester l’accès**.

Au clic, la zone `#course-message` doit afficher :

```
Runes anciennes — accès ouvert
```

si le cours est disponible, ou :

```
Alchimie élémentaire — cours indisponible
```

sinon.

### Contraintes

- récupérer la zone `#course-message` et vérifier qu’elle existe, comme cela a déjà été fait pour les autres éléments du DOM ;
- réutiliser le bouton déjà présent dans `renderCourse` et changer son texte en **Tester l’accès** ;
- lorsqu’un bouton est cliqué, utiliser les informations du **cours correspondant à ce bouton** pour construire le message ;
- le clic doit modifier uniquement la zone `#course-message` : la liste des cours ne doit pas être reconstruite ;
- ne pas créer de nouvel état comme `selectedCourse` ou `selectedCourseId`.

> Vous avez déjà, dans `renderCourse(course)`, le cours courant et son bouton.

> À vous de relier le clic à la zone de message avec les outils DOM et les conditions vus pendant la séance.

# Bonus 4 : Le compteur de places enchanté

## Situation

Une salle possède un nombre limité de places.

HTML fourni :

```html
<section>
  <h2>Atelier de potions</h2>

  <p>
    Places restantes :
    <strong id="places">3</strong>
  </p>

  <button id="reserve">
    Réserver une place
  </button>

  <button id="cancel">
    Annuler une réservation
  </button>
</section>
```

## Mission

Écrire le TypeScript permettant de :

- démarrer avec 3 places ;
- retirer une place au clic sur **Réserver** ;
- ajouter une place au clic sur **Annuler** ;
- ne jamais descendre sous 0 ;
- ne jamais dépasser 3 ;
- mettre à jour le DOM après chaque action ;
- désactiver le bouton Réserver lorsqu’il ne reste plus de place ;
- désactiver Annuler lorsque les 3 places sont libres.

Contraintes :

- vérifier les éléments DOM nécessaires ;
- aucune autre **variable d’état** globale que `availablePlaces` ; les constantes du DOM et `capacity` restent autorisées ;
- créer une fonction `render()` dédiée à l’affichage.

> Ce bonus anticipe légèrement une syntaxe du créneau suivant :

> `querySelector<HTMLButtonElement>(...)` indique à TypeScript que l’on s’attend à récupérer un bouton.

> La propriété `disabled` est un booléen : `true` désactive le bouton, `false` le laisse actif. Dans la vérification du DOM, `||` signifie « ou » : si au moins un élément manque, on arrête l’exécution.

### Extension

Afficher :

```
COMPLET
```

lorsque le compteur atteint zéro.
